## Grok Bot behaviour we need to know
- Custom MCP server from chat: a bot has a built-in tool to add an MCP server and another to start authentication, which shows a connect/Authorize card in chat that resumes the bot when done. Exact card wording and steps were not exercised in this build.
- Connector sharing: yes, connectors are per user account, not per bot. This brand-new bot could see the account's existing `testchimp` connectors (prod and staging) immediately. A connector can hold multiple accounts (there are tools to remove/rename an account on a connector); whether a second bot can re-run Authorize to pick another project wasn't tested.
- Per-bot storage: bots have their own memory (agent-scoped, separate from a shared user memory every bot can read). Secrets requested through a masked input are saved for the bot as an env var (`process.env.NAME`); whether that's strictly per-bot wasn't verified. Important: all of a user's bots share ONE cloud computer (same filesystem, installed tools, browser logins; separate desktops), so `testchimp bot save-binding` on the cloud computer and the installed skill/CLI are visible to every bot of that user. Skills are also a global library across all the user's bots. One bot can read another owned bot's transcript.
- Commands on the user's computer: the bot runs shell commands/file reads on a registered user computer, and each one goes through the user's local-tool approval. Node.js/npm availability depends on the user's machine (not checked here). Opening the user's browser from the bot wasn't tested.
- Couldn't follow / represent: no instructions field in templates (worked around with a skill + profile memory); multi-file skills can't be packed (bot self-installs from GitHub); no per-bot "Share as Template" button path documented, the template is staged by the bot and confirmed by the owner on a review card; Team visibility not available on this account.
